# ttpull

Keeps a local archive of your liked and bookmarked videos up to date, unattended.

- **Browser extension** (`extension/`): pushes your signed-in session to the container. Nothing else.
- **Container** (`container/`): runs a real Chromium with a saved login, checks your newest likes and
  bookmarks every 10 minutes, downloads the best-quality file for anything new, and records it in the
  archive's database.

The archive is a plain folder. **kashibox** (the player) reads it; ttpull writes it.

## Shared archive folder

ttpull and kashibox mount the **same folder**. ttpull creates and updates it; kashibox only needs to read it.
kashibox needs no viewer files (no `Archive.html`, no `app.js`).

```
<archive>/
  data/
    .appdata/
      db_videos.js      { [videoId]: { authorId, createTime, itemMute, diggCount, playCount, size } }
      db_authors.js     { [authorId]: { uniqueIds[], nicknames[], followerCount, heartCount, videoCount } }
      db_texts.js       { [videoId]: description }
      db_likes.js       { schemaVersion, user, likes: { officialList[], downloaded[], total, numDisappeared, lastRun } }
      db_bookmarked.js  { officialList[], downloaded[], total, numDisappeared, lastRun }
      backups/ttpull-<timestamp>/   copies of any database file ttpull is about to change (last 10 kept)
    Likes/{covers,videos}/<id>.jpg|.mp4
    Favorites/{covers,videos}/<id>.jpg|.mp4
```

Each database file is `window.<name>_base64="<base64(gzip(JSON))>";`. The variable names are
`dbv_base64`, `dba_base64`, `dbvd_base64`, `db_base64` (likes) and `dbb_base64` (bookmarks).
`officialList` is the site's current list, newest first; `downloaded` is what is in the archive; a video that is
in `downloaded` but no longer in `officialList` has disappeared from the site. `lastRun` is
`{ start, finish }` in milliseconds.

### First run and bootstrap

With `DB_UPDATE=write`, an empty folder (or one with no database files) is set up automatically on start,
and again before the first write: the five database files above, empty, plus the four media folders.

- It **never overwrites or modifies an existing file.** Files are created exclusively (a half-written file is never visible).
- If **some** database files exist but not all, it creates nothing and logs a warning. A person should look at it.
- Running it again changes nothing.
- It never creates viewer files.

`GET /archive/status` tells a player whether the archive exists yet:

```json
{ "initialized": true,
  "likes":     { "downloaded": 0, "official": 0 },
  "bookmarks": { "downloaded": 0, "official": 0 },
  "lastWrite": "2026-10-10T21:36:37.000Z" }
```

Counts only: no ids, names or captions. Before the archive exists: `initialized: false`, zero counts, `lastWrite: null`.
`lastWrite` is the newest modified time among the five database files.

## Safety

`DB_UPDATE` controls writes to the database files. Downloads happen regardless.

| value | behaviour |
|---|---|
| `dry` (default) | decode and check everything, log what would change, write nothing, create nothing |
| `write` | bootstrap if needed, back up each file it is about to change, then write |
| `off` | never touch the database |

A file is checked before it is touched: ttpull must be able to decode it and re-encode it to identical data,
otherwise it refuses and logs an error.

For a new standalone archive you want `DB_UPDATE=write`.

## Running it

```yaml
services:
  ttpull:
    image: ghcr.io/nullredvector/ttpull:latest
    ports: ["3847:3847"]
    shm_size: 1gb                       # Chromium needs more than Docker's default
    environment:
      - ARCHIVE_DIR=/app/archive
      - DB_UPDATE=write
    volumes:
      - /path/to/archive:/app/archive   # shared with kashibox
      - /path/to/state:/data            # browser login, session, retry state
```

Point kashibox at the same `/path/to/archive` (read-only is enough). Then load the extension, sign in to the site in
your browser, and click **Push Session Now**. See `docker-compose.yml` for every setting.

Useful endpoints: `GET /status`, `GET /logs`, `GET /archive/status`, `POST /sync[?test=1|full=1]`,
`POST /verify[?refresh=1]` (checks the archive against the site's lists), `POST /notify/test`.

cd container && npm test
